## Task 1 — KeychainStore 반환값 검사 (C3 보안)

**파일**: `Sources/AutoLock/KeychainStore.swift`

**문제**: `SecAccessCreate`, `SecAccessCopyACLList`, `SecACLSetContents`의 OSStatus 반환값을 한 번도 검사하지 않음. 실패해도 그대로 진행해 silent ACL이 적용 안 된 채 항목 저장 가능 → 자동 해제 시 Keychain 다이얼로그가 사용자 부재 중 떠서 멈춤.

**Specification**:

1. `save(password:)`에서 다음 호출의 반환값을 모두 검사:
   - `SecAccessCreate(...)` → `errSecSuccess`가 아니면 즉시 `false` 반환
   - `SecAccessCopyACLList(...)` → 실패 시 즉시 `false`
   - `SecACLSetContents(...)` → 한 번이라도 실패 시 즉시 `false`
2. 실패 시 stderr에 진단 메시지 1줄 출력 (`AutoLock[keychain]: <step> failed status=<n>`).
   - 진단은 디버그 빌드/배포 빌드 모두에 출력 (사용자가 운영 중 실패 시 로그로 추적 가능해야 함).
3. 성공 경로는 그대로 유지 (silent ACL 동작 변경 없음).

**Acceptance**:
- 테스트 없음 (Phase 2의 KeychainStore는 통합 테스트 영역). 수동 검증:
  - 정상 경로: 메뉴에서 암호 저장 후 `KeychainStore.hasPassword()` true
  - 실패 시뮬레이션 어려우니 코드 리뷰로 가드 검증

**금지**:
- ACL 빌드 실패 시 silent ACL 없이 저장 강행 금지 (보안 결정 회피 X)
- 이번 task에서 zeroize/메모리 wipe까지 추가하지 말 것 (별도 작업)

## Task 2 — Settings.enabled=false 시 BLE 스캔 정지 (C13 배터리)

**파일**: `Sources/AutoLock/ProximityController.swift`

**문제**: `settings.$enabled.sink`에서 `enabled=true`일 때 `scanner.startScanning()`만 호출, false 시 `stopScanning()` 미호출. 사용자가 명시 토글 OFF해도 BLE 라디오는 계속 스캔 → 배터리/신뢰성 이슈.

**Specification**:

1. `init()`의 `settings.$enabled.sink` 클로저:
   ```swift
   if enabled {
       self.scanner.startScanning()
   } else {
       self.scanner.stopScanning()
   }
   self.status = enabled ? .watching : .idle
   ```
2. `BLEScanner.stopScanning()`이 이미 존재하는지 확인. 없으면 추가:
   ```swift
   func stopScanning() {
       guard central.isScanning else { return }
       central.stopScan()
       isScanning = false
   }
   ```

**Acceptance**:
- 수동 검증: 토글 ON → `Console.app`에서 광고 패킷 들어옴 확인 → 토글 OFF → 광고 패킷 더 이상 안 들어옴
- Phase 2에서 `BLEScanner` 모킹 가능해지면 자동 테스트 추가

**금지**:
- `enabled` 변경 외에 다른 정지 트리거 추가 금지 (예: 등록 디바이스 0개일 때 정지 등 — 별도 결정 사항)

## Task 3 — Timer를 .common RunLoop mode로 통일 (C9/C10)

**파일**: `Sources/AutoLock/ProximityController.swift`, `Sources/AutoLock/BLEScanner.swift`

**문제**: `Timer.scheduledTimer(withTimeInterval:repeats:)`는 default RunLoop mode에만 등록. 메뉴 트래킹/드래그 중 정지. `CountdownOverlay`만 `.common` 사용 — 일관성 결여.

**Specification**:

1. `ProximityController.evaluationTimer` 생성을 `.common` mode로 변경:
   ```swift
   let timer = Timer(timeInterval: LockTuning.evaluationIntervalSeconds, repeats: true) { [weak self] _ in
       Task { @MainActor in self?.evaluate() }
   }
   RunLoop.main.add(timer, forMode: .common)
   evaluationTimer = timer
   ```
2. `BLEScanner.startPruneTimer` 동일 패턴으로 변경.
3. 다른 `Timer.scheduledTimer` 호출이 있으면 모두 `.common`으로 통일 (grep 확인).

**Acceptance**:
- 수동 검증: 메뉴를 열어둔 상태로 30초 대기 → 닫고 보면 statusMessage가 정상 갱신됨
- Phase 2 테스트는 가짜 Clock 주입 후 `evaluate()` 직접 호출이라 RunLoop mode와 무관

**금지**:
- 인터벌(`1.0` / `LockTuning.evaluationIntervalSeconds`) 변경 금지

## Task 4 — awaySince를 enum 상태로 모델링 (C7)

**파일**: `Sources/AutoLock/ProximityController.swift`

**문제**: `awaySince: Date?`가 4곳에서 nil 리셋됨. 한 곳이라도 누락되면 다음 사이클에 잘못된 카운트다운 표시. 컴파일러가 못 잡음.

**Specification**:

1. 새 enum 타입 도입:
   ```swift
   private enum LockTimerState {
       case idle
       case counting(start: Date)
   }
   ```
2. `awaySince: Date?` → `lockTimer: LockTimerState = .idle`로 교체.
3. 기존 `awaySince = nil` 모두 `lockTimer = .idle`로 교체.
4. 기존 `awaySince = Date()` (handleAway 진입 시 nil이면) → 패턴 매칭으로 명확히:
   ```swift
   let startedAt: Date
   switch lockTimer {
   case .idle:
       startedAt = Date()
       lockTimer = .counting(start: startedAt)
   case .counting(let s):
       startedAt = s
   }
   ```

**Acceptance**:
- 빌드 통과 후 시나리오:
  1. 디바이스 멀어짐 → 카운트다운 시작 → 신호 회복 → 카운트다운 사라짐
  2. 다시 멀어짐 → 카운트다운이 처음부터 다시 시작 (이전 시작 시각 사용 X)
- Phase 2의 `handleAway` 테스트가 이 동작을 검증

**금지**:
- 다른 상태 변수(`state`, `wakeFiredForCurrentLock`)는 건드리지 말 것

## Task 6 — Protocol 추상화 도입

**파일**: `Sources/AutoLock/ProximityProtocols.swift` (신규), 기존 정적 enum들

**Specification**:

1. 다음 protocol 신규 정의 (`ProximityProtocols.swift`):
   ```swift
   protocol ScreenLocking {
       func isLocked() -> Bool
       @discardableResult func lock() -> Bool
   }

   protocol DisplayWaking {
       @discardableResult func wake() -> Bool
   }

   protocol Clock {
       func now() -> Date
   }

   protocol BLESignaling: AnyObject {
       var devices: [UUID: DiscoveredDevice] { get }
       var isScanning: Bool { get }
       func startScanning()
       func stopScanning()
   }
   ```
2. 기존 `ScreenLocker`, `DisplayWaker`를 conform하는 wrapper struct 작성:
   ```swift
   struct SystemScreenLocker: ScreenLocking {
       func isLocked() -> Bool { ScreenLocker.isScreenLocked() }
       func lock() -> Bool { ScreenLocker.lock() }
   }
   struct SystemDisplayWaker: DisplayWaking {
       func wake() -> Bool { DisplayWaker.wake() }
   }
   struct SystemClock: Clock {
       func now() -> Date { Date() }
   }
   ```
3. `BLEScanner`를 `BLESignaling` conform.
4. `ProximityController`의 `private init()`을 의존성 주입 가능하게 변경 (싱글톤 유지하되 `init` internal로):
   ```swift
   init(scanner: any BLESignaling = BLEScanner(),
        settings: Settings = .shared,
        locker: ScreenLocking = SystemScreenLocker(),
        waker: DisplayWaking = SystemDisplayWaker(),
        clock: Clock = SystemClock()) { ... }
   ```
5. 본문에서 `ScreenLocker.isScreenLocked()` / `ScreenLocker.lock()` / `DisplayWaker.wake()` / `Date()` 호출을 주입된 인스턴스 호출로 변경.

**Acceptance**:
- `ProximityController.shared`는 그대로 작동 (default arg)
- `swift build` 통과
- 테스트에서 fake 인스턴스 주입 가능

**금지**:
- `CountdownOverlay`/`UnlockTrigger`/`KeychainStore`/`PermissionPrompt`/`LaunchAtLogin`까지 추상화 금지 (이번 범위 밖, 우선순위 낮음)
- `Settings`는 추상화 안 함 (테스트에서는 init 새로 만들거나 UserDefaults suite 분리)

## Task 7 — ProximityController 테스트 (6건)

**파일**: `Tests/AutoLockTests/ProximityControllerTests.swift`

**Specification**:

테스트 헬퍼 (in-test):

```swift
final class FakeScanner: BLESignaling {
    var devices: [UUID: DiscoveredDevice] = [:]
    var isScanning = false
    func startScanning() { isScanning = true }
    func stopScanning() { isScanning = false }
}
final class FakeLocker: ScreenLocking {
    var locked = false
    var lockCallCount = 0
    func isLocked() -> Bool { locked }
    func lock() -> Bool { locked = true; lockCallCount += 1; return true }
}
final class FakeWaker: DisplayWaking {
    var wakeCallCount = 0
    func wake() -> Bool { wakeCallCount += 1; return true }
}
final class FixedClock: Clock {
    var current: Date
    init(_ d: Date = Date()) { self.current = d }
    func now() -> Date { current }
}
```

**6개 테스트** (모두 `@MainActor`):

1. **`test_evaluate_disabled_keepsScreenUnlocked`**
   - settings.enabled = false
   - controller.evaluate()
   - assert: state == .unknown, locker.lockCallCount == 0

2. **`test_evaluate_noTrackedDevices_keepsScreenUnlocked`**
   - settings.enabled = true, trackedDevices = []
   - assert: state == .unknown, locker.lockCallCount == 0, status == .awaitingDevice

3. **`test_evaluate_signalAboveThreshold_isNear`**
   - tracked device 1개, RSSI = threshold + 10, lastSeen = now
   - assert: state == .near, locker.lockCallCount == 0

4. **`test_evaluate_signalLongAbsence_locksImmediately`**
   - tracked device, lastSeen = now - (gracePeriod * 2 + 1)
   - assert: locker.lockCallCount == 1, state == .away

5. **`test_evaluate_signalCrashed_locksImmediately`**
   - RSSI <= definitiveAwayThreshold
   - assert: locker.lockCallCount == 1

6. **`test_handleAway_recoveryResetsCountdown`**
   - 멀어짐 → handleAway 진입 → clock 3초 진행 → 다시 강한 신호
   - 그 후 다시 멀어짐 → assert: lockTimer가 새로 시작됨 (기존 시작 시간 사용 X)

**Acceptance**:
- `swift test` 실행 시 6개 테스트 모두 통과
- 테스트가 BLE 하드웨어/실제 ScreenLocker 호출 안 함

**금지**:
- async/await 테스트 회피 (Combine sink 결과 대기는 expectation 필요 — 복잡해지면 동기 호출만)
- 1초 타이머 의존 테스트 금지 (timer 트리거 대신 evaluate() 직접 호출)
- UI 컴포넌트(CountdownOverlay) 테스트 금지 — 별도 작업

## Task 8 — Settings 클램핑 + BLEScanner 테스트 (1건씩)

**파일**: `Tests/AutoLockTests/SettingsTests.swift`, `Tests/AutoLockTests/BLEScannerTests.swift`

**Specification**:

1. **`SettingsTests`**:
   - `test_thresholdMagnitude_clampsBelow40`: UserDefaults에 30 저장 → init → assert thresholdMagnitude == 40
   - `test_thresholdMagnitude_clampsAbove100`: 150 저장 → assert == 100
   - `test_gracePeriodSeconds_clampsBelow15`: 5 저장 → assert == 15
   - `test_gracePeriodSeconds_clampsAbove60`: 90 저장 → assert == 60

   각 테스트는 별도 UserDefaults suite로 격리:
   ```swift
   let defaults = UserDefaults(suiteName: "test-\(UUID().uuidString)")!
   defaults.set(30, forKey: "thresholdMagnitude")
   ```
   주의: 현재 `Settings.init`이 `UserDefaults.standard` hardcode임 → init에 `UserDefaults` 인자 추가 필요 (Task 6의 정신과 동일).

2. **`BLEScannerTests`**:
   - `test_smoothing_combinesNewAndPriorRssi`: 직접 EWMA 헬퍼 함수만 테스트 (`smoothingFactor * new + (1-factor) * prev`로 결과 계산). `BLEScanner` 인스턴스 만들지 말고 `LockTuning.rssiSmoothingFactor` 사용한 순수 함수 추출:
     ```swift
     extension BLEScanner {
         static func smooth(prev: Double, new: Int) -> Double {
             prev * (1 - LockTuning.rssiSmoothingFactor) + Double(new) * LockTuning.rssiSmoothingFactor
         }
     }
     ```
     테스트는 `BLEScanner.smooth(prev: -70, new: -60)` 결과가 expected 값에 근접한지.

**Acceptance**:
- `swift test` 4 + 1 = 5 추가 테스트 통과 (총 11개+)

**금지**:
- 실제 `CBCentralManager` 호출 금지
- `UserDefaults.standard` 직접 만지는 테스트 금지 (격리 필수)
